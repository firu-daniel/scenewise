# Task plan review — iteration 1

The three Must Fix findings of iteration 0 (the job-folder check in Task 1, the job-folder rows in Task 4, and the basename-job-id case and whole-tree snapshot in Task 6) are resolved in the plan as it now stands.

## Must Fix

1. **`task_1_plan.md` — refusal (a) tests `urlsplit(requested).query` / `.fragment`, which are `""` for an empty `?` or `#`. So `file:///srv/artifacts/shared?` and `file:///srv/artifacts/shared#` get through, and the gap the refusal exists to close stays open.**
   Work bullet 2 (a) refuses a requested prefix only when "`urlsplit(requested)` carries a `query` or a `fragment`". It gives the reason itself: "The appended `/{job_id}/a{n}/…` would otherwise land in the query or fragment, and every job would write the same file." The Goal also promises to refuse "a query, a fragment". But `urllib.parse.urlsplit` cannot tell an empty query or fragment from an absent one. For `file:///srv/artifacts/shared?` and `file:///srv/artifacts/shared#`, both `.query` and `.fragment` are `""`, so (a) does not fire. Then:
   - (b) passes, because the path is `/srv/artifacts/shared`.
   - (c) normalises the folder `file:///srv/artifacts/shared?/j` through `_location`, which reads only the path `/srv/artifacts/shared`. That is not under the state path, so the prefix is accepted.
   - `artifacts_prefix` returns `file:///srv/artifacts/shared?/{job_id}`. `publish` writes `…?/{job_id}/a1/audio.wav` and `…?/{job_id}/a1/result.json`. `LocalBlobStore._path` reads `url2pathname(parts.path)`, so both URIs land on the one path `/srv/artifacts/shared` for every job.
   - The result: every job overwrites the same file inside an artifact root, and `audio.wav` and `result.json` overwrite each other.

   This is the same string-versus-resolved gap the task prompt asks planning to look for in "the other callers". It also breaks the `artifacts_prefix` guarantee the plan keeps ("so one job can never write into another job's folder"). The state prefix itself stays safe, because (c) sees the path, but the refusal as specified does not do what the plan says it does. Task 4's rows (`x?a=b`, `x#f`) would pass against it.
   **Fix:** In `task_1_plan.md` Work bullet 2 (a), test the raw string: refuse when `"?" in requested or "#" in requested`. Do not rely on urlsplit's `query` / `fragment`. Say why: urlsplit returns `""` for an empty `?` / `#`. Add `file:///srv/artifacts/x?` and `file:///srv/artifacts/x#` to the "Refused on shape" Verification list.
