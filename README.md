# scenewise

scenewise is an open-source, self-hosted Python service that understands video: captions, summaries, chapters, a
moderation second opinion and labels. Adopters run it in their own cloud and pay their own costs. It is called through
one generic HTTP endpoint (`POST /v1/jobs`, Cloud Tasks semantics) or a command line; it has no consumer-specific code.

- [ARCHITECTURE.md](ARCHITECTURE.md): how the code is organised and the gates that keep it that way.

## Status

**Skeleton.** The repository has the architecture's full shape (layers `service > (adapters | app) > ports > domain`,
every port as a `Protocol`, the job lifecycle, every gate in CI), and **one thin stage wired end to end: `audio`**,
which extracts a video's or audio file's sound as one 16 kHz mono 16-bit PCM WAV with ffmpeg. It runs from the CLI and
through the HTTP job endpoint, with a compare-and-swap job record on a local single-host store.

No model runs yet. The stages and the adapters that need models arrive with the roadmap:

| Arrives with | Adapters and pieces |
|---|---|
| Item 1, captions | Silero VAD, Whisper-tiny language ID on onnxruntime, Parakeet on sherpa-onnx (primary) and onnx-asr (second) (`asr` extra); the opt-in faster-whisper fallback (`asr-whisper`, brings PyAV's GPL x264/x265, not in published images; U16); HLS and segment-list audio inputs; `tests/models.lock` and the model test tier; `NOTICE` |
| Item 2, summaries and chapters | Claude Haiku through the Anthropic SDK, first-party or Vertex AI (`llm-anthropic`); the OpenAI-compatible adapter (httpx) |
| Items 3 and 4, moderation and labels | open_clip / SigLIP 2 and the tier-1 classifier (`vision` + a `torch-*` selector); visual inputs and frame sampling; `scenewise calibrate` |
| Deployment work | the GCS blob store and OIDC/HMAC callbacks (`gcs`), the Dockerfile, `scenewise run-job` |

## Requirements

- Python 3.12, 3.13 or 3.14.
- **ffmpeg and ffprobe** on `PATH` (major version 6 or later), or set `SCENEWISE_MEDIA__FFMPEG` and
  `SCENEWISE_MEDIA__FFPROBE`. scenewise checks them at start-up and refuses to start without them. ffmpeg is always
  handed a local file, never a URL.
- [uv](https://docs.astral.sh/uv/) 0.12.23 (the version `pyproject.toml` pins).

## Run the audio stage

```sh
uv sync --extra service

# Command line: writes ./out/audio.wav and prints the result document.
uv run scenewise analyse path/to/video.mp4 --out out

# HTTP: the push endpoint runs the job and answers when it is terminal.
export SCENEWISE_INPUTS__LOCAL_ROOTS='["/absolute/path/to/media"]'
uv run uvicorn --factory scenewise.service.http.app:create_app --port 8080
curl -s localhost:8080/v1/jobs -H 'content-type: application/json' -d '{
  "schema_version": "1", "job_id": "demo-1", "stages": ["audio"],
  "audio": {"kind": "file", "uri": "file:///absolute/path/to/media/video.mp4"},
  "delivery": {}
}'
curl -s localhost:8080/v1/jobs/demo-1
```

The job record is `{state_prefix}/{job_id}/status.json` (default `./.scenewise/state`), and each attempt's artifacts
(`result.json`, `audio.wav`) are under `…/{job_id}/a{attempt}/`; follow the record's `result_uri`, never build the path.
`file://` inputs are accepted only below `SCENEWISE_INPUTS__LOCAL_ROOTS` (the CLI adds the given file's directory),
never from the state directory. A request's `delivery.artifacts.uri_prefix` must lie below
`SCENEWISE_SERVICE__ARTIFACT_ROOTS`, and its artifacts go to `{uri_prefix}/{job_id}/a{attempt}/`.

## Extras

The base install has no model runtime and no torch. Extras: `service` (FastAPI, uvicorn), `asr` (CPU only),
`llm-anthropic`, `vision`, `gcs`, and the selector pair `torch-cpu` / `torch-cu130`. With uv, the selectors route
torch and torchvision to the PyTorch CPU or CUDA 13 index. **pip users** do not get that routing: for a CPU install,
pass `--index-url https://download.pytorch.org/whl/cpu` (PyPI's default torch on Linux is the CUDA 13 build).

## Development

Every gate CI runs is in [.github/workflows/ci.yml](.github/workflows/ci.yml); all tool configuration is in
`pyproject.toml`. Locally:

```sh
uv sync --extra service --extra asr --extra llm-anthropic --extra vision --extra gcs --extra torch-cpu
uv run ruff format --config pyproject.toml --check . && uv run ruff check --config pyproject.toml .
uv run mypy --config-file pyproject.toml && uv run lint-imports --no-cache --config pyproject.toml
uv run pytest -c pyproject.toml --cov --cov-config=pyproject.toml
```

Test media are generated by [tests/fixtures/generate.sh](tests/fixtures/generate.sh) with ffmpeg's lavfi sources;
nothing is downloaded. Keys never go into the repository: copy `.env.example` to `.env.local` (gitignored).
