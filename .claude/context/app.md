# The `app` layer

> **Read this when:** the change you are implementing or reviewing lands in `src/scenewise/app` — a use case (acquisition, stages, runner, publish, delivery), the port bundle in `src/scenewise/app/deps.py`, or the versioned wire contract in `src/scenewise/app/contract/`. **Skip when:** it lands in `domain`, `adapters`, `service`, `src/scenewise/ports.py` or `tests`; each has its own document, and the rules spanning every layer live in `.claude/context/conventions.md`, which this file assumes you have read.

**Purpose.** The rules this layer's implementer and its reviewer both hold a change in `src/scenewise/app` to. Rules that govern more than one layer are owned by `.claude/context/conventions.md`; this file states only what they mean here.

## Responsibility

- `app` holds the use cases and the wire contract, all synchronous: plain functions that fetch through ports, call pure `domain` code and return domain data (`src/scenewise/app/__init__.py` docstring; `src/scenewise/app/stages.py` module docstring; `ARCHITECTURE.md` §6). No `async`, no anyio — the async edge is `src/scenewise/service/http` (owner: `.claude/context/conventions.md` `## Stack`, "Transport").
- Not here: interpreting model output (pure `domain`), loading or running a model or SDK (an adapter), reading settings or choosing back ends (`service`). A task that needs any of those has drifted out of this layer (`ARCHITECTURE.md` §3, §13).
- `src/scenewise/app/contract/` is the wire contract: Pydantic models plus the wire ↔ domain mapping. Use-case modules never build a wire document themselves; they call `src/scenewise/app/contract/mapping.py` (`src/scenewise/app/publish.py` `publish`; `src/scenewise/app/delivery.py` `_Delivery.write`, `_Delivery.answer`; owner: `.claude/context/conventions.md` `## Shared state, storage paths and the wire contract`).

## Dependencies

- `app` imports `ports`, `domain`, the stdlib, `pydantic`, `pydantic_core` and `structlog` — never `adapters`, never `service` (owner: `.claude/context/conventions.md` `## Dependency direction`). Consequence here: a deployment value reaches a use case as an argument — `DeliveryPolicy`, `AttemptInfo`, `deadline=` — never by reading `Settings` (`src/scenewise/app/delivery.py` `DeliveryPolicy`, `handle_delivery`; `src/scenewise/app/runner.py` `run_job`).
- A use case receives its ports through `Dependencies` (`src/scenewise/app/deps.py`), built once by `service.bootstrap`; nothing per job is stored in it (`src/scenewise/app/deps.py` module docstring). An optional back end is a `| None = None` field, and `enabled_stages()` derives which stages a deployment offers from which back ends are present (`src/scenewise/app/deps.py` `Dependencies`, `enabled_stages`).
- Two blob stores, never swapped: request inputs are read through `deps.inputs`; job records and artifacts are written through `deps.store` (`src/scenewise/app/deps.py` field comments; `src/scenewise/app/runner.py` `run_job` passes `store=deps.inputs`; `src/scenewise/app/publish.py` `publish`; `docs/skeleton-notes.md` A6, the input/output split from review r1 finding 1).

## Use-case rules

- **Acquisition** is a `@contextmanager` that materialises the input through the store and yields a domain value valid inside the context; ffmpeg only ever sees the local file the store materialised (`src/scenewise/app/audio.py` `acquire_audio` docstring; `ARCHITECTURE.md` §11). A source kind not yet supported raises `UnsupportedMediaError(code="unsupported_media", …)`; the `match` over the source union ends in `case _: assert_never(source)` (`src/scenewise/app/audio.py` `acquire_audio`).
- **Stages** are one function per stage in `src/scenewise/app/stages.py`; `src/scenewise/app/runner.py` orders them with `domain.plan.ordered` and dispatches each through `_dispatch`'s `match stage:`. A stage that is enabled but has no `case` there is `InternalError(code="invariant_violation")` (`src/scenewise/app/runner.py` `_dispatch`).
- **Errors inside a stage fail that stage only**: `_run_stage` re-raises `RetryableError` (it fails the attempt), turns any other `ScenewiseError` into `Failed` with its code and category, a `ValueError` into `invariant_violation`, and any other exception into `unexpected` logged with `log.exception` (`src/scenewise/app/runner.py` `_run_stage`; `ARCHITECTURE.md` §9). **Errors before the stages fail the whole job** — a requested stage outside `deps.enabled_stages` is `InputError(code="stage_unavailable")` (`src/scenewise/app/runner.py` `run_job`; `src/scenewise/app/delivery.py` `_run`).
- **Deadlines** are `time.monotonic()` values passed as the keyword `deadline`; the runner calls `remaining(deadline)` between stages, which raises `InternalError(code="deadline_exceeded")` (`src/scenewise/app/runner.py` `remaining`, `run_job`). Record timestamps are wall-clock `time.time()` / `AttemptInfo.now` (`src/scenewise/app/delivery.py` `_terminal`, `_attempt`).
- **Logging context** is bound with `structlog.contextvars.bound_contextvars` at the level that knows it — `job_id` in `handle_delivery` and `run_job`, `attempt` in `_attempt`, `stage` around each stage — never passed as a parameter (`src/scenewise/app/delivery.py`, `src/scenewise/app/runner.py` `bound_contextvars`; logger and event-name rules owned by `.claude/context/conventions.md` `## Logging`).

## Job record, artifacts and storage paths

- Record-write ownership, the `if_generation` compare-and-swap on every record write and where notify sits are owned by `.claude/context/conventions.md` `**Source of truth.**`. Here: the claim's returned generation is the attempt's fencing token, so a superseded attempt cannot overwrite a later terminal record (`src/scenewise/app/delivery.py` module docstring, `_Delivery.write`). A `WriteConflictError` is answered with `TryLater` and is never retried in-process; it carries `job_in_progress`, except when releasing a claim, where it carries the error being released (`src/scenewise/app/delivery.py` `_attempt`, `_finish`, `_give_up`, `_release`).
- Delivery order is decide → claim → parse → run → publish → terminal record; the request body is parsed with `mapping.to_domain` **inside** the claim, so a validation failure ends in a terminal `FAILED` record (`src/scenewise/app/delivery.py` module docstring, `_run`; `ARCHITECTURE.md` §7). The decision itself is the pure `domain.jobs.decide_attempt`; `handle_delivery` only matches on its result and ends in `case _: assert_never(decision)` (`src/scenewise/app/delivery.py` `handle_delivery`).
- A use case reports an outcome and never picks an HTTP status: a reused job id is `Rejected(error=JobIdConflictError(detail=…))`, and `service` maps the error to its status and renders the body (`src/scenewise/app/delivery.py` `Rejected`, `DeliveryOutcome`; `src/scenewise/service/http/push.py` `_admitted`, `_rejected`; `src/scenewise/service/http/problems.py` `http_status`).
- Reading a job's status is the use case `job_status`: an invalid id or an absent record is `None`, a store failure propagates, an unreadable record is `invariant_violation` (`src/scenewise/app/delivery.py` `job_status`; `src/scenewise/app/contract/mapping.py` `record_from_json`).
- `src/scenewise/app/publish.py` writes artifacts only and never touches the job record (`src/scenewise/app/publish.py` module docstring; `ARCHITECTURE.md` §13 "Ownership on the delivery path").
- An `AlreadyDone` duplicate is not re-notified (`ARCHITECTURE.md` §7 step 7, "`AlreadyDone` duplicates are not re-notified"; attributed — the code sends none yet, `src/scenewise/app/delivery.py` module docstring "Callbacks (step 7's notify) arrive with the HTTP callback adapter").
- The record's path and the attempt layout are owned by `.claude/context/conventions.md` `**Storage paths.**`. Here: the record's URI comes only from `record_uri`; an artifact's call site appends only its file name to a prefix `artifacts_prefix` or `attempt_prefix` returned (`src/scenewise/app/delivery.py` `record_uri`, `RECORD_FILE_NAME`; `src/scenewise/app/publish.py` `publish`, `AUDIO_FILE_NAME`, `RESULT_FILE_NAME`). `artifacts_prefix` falls back to `job_prefix` when no `uri_prefix` is requested; a requested `uri_prefix` gets the job id appended and may not lie under the state prefix — `InputError(code="uri_not_allowed")` (`src/scenewise/app/delivery.py` `artifacts_prefix`; `docs/skeleton-notes.md` A6).
- Constant naming and placement are owned by `.claude/context/conventions.md` `## Constants and configuration`. Here: `app` imports a `domain` constant from its owning module rather than redefining it (`JOB_ID_PATTERN` and `FIRST_ATTEMPT` from `src/scenewise/domain/jobs.py` in `src/scenewise/app/contract/requests.py`, `src/scenewise/app/contract/records.py` and `src/scenewise/app/delivery.py`; `MS_PER_SECOND` from `src/scenewise/domain/time.py` in `src/scenewise/app/contract/mapping.py`). `app`'s shared constants with no owning module are in `src/scenewise/app/constants.py`: `JSON_MEDIA_TYPE`, also imported by `service`, and the wire schema version `SchemaVersionV1` / `SCHEMA_VERSION_V1`. The attempt folder's file names belong to `src/scenewise/app/publish.py` (`AUDIO_FILE_NAME`, `RESULT_FILE_NAME`); `src/scenewise/service/cli.py` imports `AUDIO_FILE_NAME` from there.

## The wire contract (`src/scenewise/app/contract/`)

- Public models carry the schema version as a `V1` suffix; versioning and the `frozen` / `extra="forbid"` split are owned by `.claude/context/conventions.md` `## Shared state, storage paths and the wire contract`. Here: request models subclass `_Input` (`extra="forbid"`, `frozen=True`) so a typo or version skew fails loudly; output models subclass `_Output` (`frozen=True`) (`src/scenewise/app/contract/requests.py` module docstring, `_Input`; `src/scenewise/app/contract/results.py` `_Output`).
- `schema_version` is a wire concern only: every v1 document types it as the alias `SchemaVersionV1`, outputs default it to `SCHEMA_VERSION_V1`, `record_to_json` stamps it and `record_from_json` validates and drops it, so the domain `JobRecord` has no such field (`src/scenewise/app/constants.py`; `src/scenewise/app/contract/mapping.py` `record_to_json`, `record_from_json`; `src/scenewise/domain/jobs.py` `JobRecord`).
- Output documents only grow within `schema_version` "1": later stages add fields, never remove them, and clients ignore unknown fields (`src/scenewise/app/contract/results.py` module docstring).
- A wire field is added with the feature that reads it, not ahead of it (`src/scenewise/app/contract/requests.py` module docstring; `docs/skeleton-notes.md` A5).
- A union on the wire is a `Literal["…"]` `kind` field plus `Field(discriminator="kind")` (`src/scenewise/app/contract/requests.py` `AudioInputV1`).
- A serialized name is the Python attribute name, snake_case, with no `alias` (owner: `.claude/context/conventions.md`; read off `src/scenewise/app/contract/`).
- `src/scenewise/app/contract/mapping.py` is named `to_domain()` for requests and `*_json()` for every document it emits; each returns `bytes` from `model_dump_json(…).encode()` (`src/scenewise/app/contract/mapping.py` module docstring, `record_to_json`, `status_json`, `result_json`, `rejection_json`). `to_domain` turns every `ValidationError` and domain `ValueError` into `InputError(code="invalid_request")`; an unreadable stored record is `InternalError(code="invariant_violation")` (`src/scenewise/app/contract/mapping.py` `to_domain`, `record_from_json`).
- A validation error is summarised with field paths and messages only — `errors(include_input=False, include_url=False)` — because inputs may hold URIs (`src/scenewise/app/contract/mapping.py` `_validation_summary`; D8 owned by `.claude/context/conventions.md` `## Logging`).
- The envelope is parsed leniently before anything else so a record can be keyed: `parse` returns `None` only for a body that is not a JSON object or has no valid `job_id` (`src/scenewise/app/contract/envelope.py` module docstring, `parse`). `request_digest` is the sha256 of `json.dumps(document, sort_keys=True, separators=(",", ":"))` with the default ASCII escaping, pinned by a property test (`src/scenewise/app/contract/envelope.py` `request_digest`; `docs/skeleton-notes.md` G20).

## Surfaces this layer does not have

No UI framework, client-side state container, localization, theming or sizing accessor, shared UI components, interactive-test attributes, navigation module or route/screen registry — scenewise is headless (owner: `.claude/context/conventions.md` `## Surfaces this project does not have`). HTTP routes are `service`'s.

## The set that accompanies a new unit here

- **Stage:** its function in `src/scenewise/app/stages.py`; its `case` in `src/scenewise/app/runner.py` `_dispatch`; its back-end condition in `src/scenewise/app/deps.py` `enabled_stages`; its name in `StageNameV1` and a field on `StageResultsV1` with its `*StageV1` model (`src/scenewise/app/contract/requests.py`, `src/scenewise/app/contract/results.py`); its result mapping in `src/scenewise/app/contract/mapping.py` `result_json`; unit tests (read off how `audio` is wired through those symbols).
- **Input kind:** the domain dataclass in its union, a `V1` model in the discriminated union, a `case` in the mapping (`src/scenewise/app/contract/mapping.py` `_audio`) and in acquisition (`src/scenewise/app/audio.py` `acquire_audio`); mypy's exhaustive-`match` names every place (owner: `.claude/context/conventions.md` "The set that accompanies a new unit").
- **Wire field, use-case function:** as `.claude/context/conventions.md` "The set that accompanies a new unit" states.

## Example

> A stage's failure is contained to that stage unless retrying could help. `src/scenewise/app/runner.py` (`_run_stage`) lets a `RetryableError` propagate so `src/scenewise/app/delivery.py` (`_attempt`) releases the lease and answers `TryLater`, while a `ScenewiseError` becomes `Failed(error_code=e.code, category=…)` and the job ends `partial` rather than burning retries on a deterministic fault.
